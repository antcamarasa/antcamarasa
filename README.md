<h3 align="center">Mais.</h3>

Écrire du code n'a jamais été le métier.

| L'IA sait faire | L'ingénieur doit comprendre |
|---|---|
| Écrire le code | Pourquoi il plante |
| Générer une API | Pourquoi elle est lente |
| Proposer un correctif | S'il est juste |
| Recopier un pattern | La mémoire, le réseau, le système en dessous |

Et cette promesse n'est pas nouvelle. Chaque abstraction l'a déjà faite :

```text
1957  Compilateurs  →  « Plus besoin de comprendre la machine. »
2005  Frameworks    →  « Plus besoin de comprendre le web. »
2006  Cloud         →  « Plus besoin de comprendre les serveurs. »
2022  IA            →  « Plus besoin de comprendre le code. »
```

À chaque fois, quand tout casse, on appelle la même personne : celle qui comprend le système.

> [!IMPORTANT]
> **L'IA a rendu le code gratuit. Elle a rendu la compréhension rare.**

On ne m'embauchera pas pour taper du code. On m'embauchera pour savoir ce qu'il fait quand il tourne, pour relire, juger et corriger ce que la machine produit, et pour comprendre le système en entier, de la mémoire jusqu'au réseau.

<h3 align="center"><b>⚡ Short cut makes long delay ⚡</b></h3>

---

## 🧱 La stratégie

Recoder ce que les outils me cachent : les structures de données, un shell, un allocateur mémoire, un serveur, une base de données.

L'IA reste un outil. Si je ne suis pas capable de relire ce qu'elle a écrit, quel est mon rôle ? Aucun.

Ce n'est pas le chemin le plus rapide. C'est celui qui dure.
